# 요구사항 명세서 (SRS)

> 문서 버전: v0.1 (2026-11-22) · 상태: 초안, 사용자 검토 대기
> 관련 문서: [ARCHITECTURE.md](ARCHITECTURE.md) · [INTERFACES.md](INTERFACES.md)

## 1. 목적

1900년대~2000년대의 로맨스·추억·그리움을 다룬 50~58초 세로 숏드라마를 AI로 자동 제작하고,
사용자가 정한 시각에 유튜브 쇼츠와 인스타그램 릴스에 자동 게시한다.
사람이 손대지 않아도 매 회차가 끝까지 가거나, 실패하면 **어디서 왜 멈췄는지 알리고 그 지점부터 다시 돌 수 있어야** 한다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 에피소드 | 게시물 1편. 대본 JSON 1개 = 영상 1개 |
| 슬롯 | 게시 예정 시각 1개 (예: 2026-11-23 20:00 KST) |
| 런(run) | 에피소드 1편을 만드는 파이프라인 1회 실행. `run_id`로 식별 |
| 스테이지 | 런을 이루는 단계 (대본, 이미지, 음성, 렌더, 게시 등) |
| 아티팩트 | 스테이지가 만든 결과 파일 (script.json, scene-01.png, final.mp4 …) |
| 게이트 | 다음 스테이지로 넘어가기 전 자동 품질 검사 |

## 3. 기능 요구사항 (FR)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 설정 파일(`config/schedule.yaml`)에 정의된 슬롯마다 파이프라인이 자동 실행된다 | 필수 |
| FR-02 | 시대(1900s~2000s 연대별)·테마를 슬롯 규칙 또는 로테이션으로 선택하고, 최근 N편과 소재가 겹치지 않게 한다 | 필수 |
| FR-03 | LLM이 [대본 스키마](../schemas/script.schema.json)를 만족하는 대본 JSON을 생성한다 | 필수 |
| FR-04 | 장면마다 이미지(9:16)를 생성한다. 인물 외형은 `characters[].look`으로 치환해 장면 간 일관성을 유지한다 | 필수 |
| FR-05 | 내레이션·대사를 TTS로 합성하고 실제 음성 길이를 측정한다 | 필수 |
| FR-06 | 실제 음성 길이에 맞춰 장면 길이를 재계산한 타임라인을 만든다 | 필수 |
| FR-07 | 이미지 + 켄번스 모션 + 음성 + BGM + 효과음 + 자막으로 1080×1920 영상을 렌더링한다 | 필수 |
| FR-08 | 커버 이미지(썸네일)를 `upload.cover_text`로 만든다 | 권장 |
| FR-09 | 유튜브에 쇼츠로 업로드한다 (제목, 설명, 해시태그, AI 합성 콘텐츠 표시) | 필수 |
| FR-10 | 인스타그램에 릴스로 게시한다 (캡션, 해시태그, 커버, AI 라벨) | 필수 |
| FR-11 | 플랫폼별 게시는 서로 독립이다. 한쪽 실패가 다른 쪽 게시를 막지 않는다 | 필수 |
| FR-12 | 사람 승인 모드를 지원한다: `auto`(바로 게시) / `review`(렌더 후 승인 대기) | 필수 |
| FR-13 | 실패·성공 결과를 알림 채널로 보낸다 (채널 종류는 미정) | 필수 |
| FR-14 | 런 하나를 특정 스테이지부터 수동으로 재실행할 수 있다 (`--from render`) | 필수 |
| FR-15 | 게시하지 않고 영상까지만 만드는 드라이런 모드가 있다 | 필수 |
| FR-16 | 사람이 직접 쓴 대본 JSON을 넣으면 대본 생성 스테이지를 건너뛴다 | 권장 |

## 4. 비기능 요구사항 (NFR)

### 4.1 신뢰성 ("절대 깨지지 않는다"의 정의)

"절대 실패하지 않는다"는 외부 API에 의존하는 한 불가능하므로, 아래 6가지를 보장하는 것으로 정의한다.

| ID | 요구사항 | 측정 기준 |
|---|---|---|
| NFR-R1 | **슬롯을 놓치지 않는다.** 게시 시각보다 미리 만들어 둔 완성본 버퍼에서 게시한다 | 버퍼 ≥ 2편 유지, 슬롯 게시 성공률 ≥ 99% |
| NFR-R2 | **재개 가능하다.** 어떤 지점에서 죽어도 마지막 성공 스테이지 다음부터 다시 돈다 | 재실행 시 완료 스테이지 재계산 0회 |
| NFR-R3 | **중복 게시가 없다.** 같은 에피소드가 같은 플랫폼에 두 번 올라가지 않는다 | 멱등 키 기반, 중복 0건 |
| NFR-R4 | **잘못된 결과물은 게시되지 않는다.** 모든 아티팩트는 스키마·게이트 검사를 통과해야 다음으로 간다 | 게이트 미통과 게시 0건 |
| NFR-R5 | **실패는 조용히 지나가지 않는다.** 모든 최종 실패는 원인·스테이지·재실행 명령과 함께 알림 | 미보고 실패 0건 |
| NFR-R6 | **외부 공급자 하나가 죽어도 대체 공급자로 이어간다** (설정된 경우) | 공급자별 폴백 체인 |

### 4.2 출력 규격

| ID | 항목 | 값 |
|---|---|---|
| NFR-F1 | 해상도·비율 | 1080×1920, 9:16 |
| NFR-F2 | 길이 | 목표 50~58초, 허용 45~59초 |
| NFR-F3 | 코덱 | H.264 (High), 30fps, yuv420p / AAC 48kHz 스테레오, MP4 (faststart) |
| NFR-F4 | 음량 | 통합 음량 -14 LUFS ±1, 트루 피크 ≤ -1 dBTP |
| NFR-F5 | 자막 | 한 줄 최대 14자, 화면 하단 안전 영역(아래 20%와 오른쪽 UI 영역 피함) |
| NFR-F6 | 파일 크기 | ≤ 100MB |

### 4.3 운영·비용·보안

| ID | 요구사항 |
|---|---|
| NFR-O1 | 편당 비용 상한(`config/pipeline.yaml`의 `budget.per_episode_usd`)을 넘으면 런을 멈추고 알린다 |
| NFR-O2 | 편당 제작 시간 ≤ 30분 (게시 버퍼가 있으므로 엄격하지 않음) |
| NFR-O3 | 모든 비밀값은 환경 변수/시크릿 저장소에만 둔다. 저장소·로그·매니페스트에 절대 기록하지 않는다 |
| NFR-O4 | 런마다 구조화 로그(JSON Lines)와 매니페스트를 남겨, 사후에 무엇이 어떤 입력으로 만들어졌는지 재현할 수 있다 |
| NFR-O5 | 스테이지 코드는 공급자 SDK에 직접 의존하지 않는다 (어댑터 인터페이스 경유) |
| NFR-O6 | 모든 아티팩트와 스키마에 `schema_version`이 있어 하위 호환을 검사할 수 있다 |

### 4.4 콘텐츠·정책

| ID | 요구사항 |
|---|---|
| NFR-C1 | 실존 노래, 가수, 상표, 실존 인물을 대본·프롬프트에 쓰지 않는다 (금칙어 게이트) |
| NFR-C2 | 유튜브 "변경되거나 합성된 콘텐츠" 표시, 인스타그램 AI 라벨을 켠다 |
| NFR-C3 | BGM·효과음은 상업적 이용이 가능한 라이선스 또는 자체 생성 음원만 쓰고, 출처를 매니페스트에 기록한다 |
| NFR-C4 | 미성년자 등장 장면은 로맨스 표현 수위를 손잡기·이어폰 나눠 듣기 수준으로 제한한다 |

## 5. 외부 제약 (플랫폼)

설계에 직접 영향을 주는 제약이다. 구현 시점에 공식 문서로 다시 확인한다.

- **YouTube Data API**: 업로드 1회가 일일 쿼터의 큰 몫(기본 10,000단위 중 약 1,600)을 쓴다. 하루 게시 편수 상한에 영향.
  또한 **감사(audit)를 받지 않은 API 프로젝트로 올린 영상은 비공개로 잠긴다.** 공개 게시 전에 감사 신청이 필요하다.
- **Instagram Graph API**: 비즈니스/크리에이터 계정 + 연결된 페이스북 페이지가 필요하다.
  릴스 게시는 컨테이너 생성 → 처리 완료 대기(폴링) → 게시 3단계이며, 영상은 공개 URL 또는 resumable 업로드로 전달해야 한다. 24시간 게시 수 제한이 있다.
- **토큰 만료**: 유튜브 OAuth 리프레시 토큰(테스트 모드 앱은 7일 만료), 인스타 장기 토큰(약 60일)은 만료 전 갱신·알림이 필요하다.

## 6. 미정 사항 (결정 필요)

| # | 항목 | 현재 가정 |
|---|---|---|
| D1 | 실행 환경 | GitHub Actions 크론 (무료 러너, 저장소와 일체) |
| D2 | 이미지 생성 공급자 | 미정. 인터페이스로 분리해 두고 1차 구현 시 결정 |
| D3 | TTS 공급자 | 미정. 한국어 품질 기준으로 선정 |
| D4 | 대본 LLM | Claude (Anthropic API) |
| D5 | 영상 모션 | 정지 이미지 + 켄번스 (비디오 생성 모델은 후순위 확장) |
| D6 | 아티팩트 저장소 | 런 디렉터리는 러너 로컬 + 완성본은 오브젝트 스토리지(예: Cloudflare R2/S3). 인스타 공개 URL 요건도 충족 |
| D7 | 알림 채널 | 미정 (텔레그램/디스코드/이메일 중 택1) |
| D8 | 게시 빈도·시각 | 미정 (예: 매일 20:00 KST) |
